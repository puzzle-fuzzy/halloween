# 设计与维护

## 边界与原则

这是单个使用者的文件工具。一个后台管理员、多个已授权设备，共享同一云盘和 OSS 账号。保留文件系统和少量 JSON 状态，避免引入业务无需求的数据库、租户或计费系统。

用户已确认现有产品完成验收。后续按新增功能进行实现和回归；下方发布检查用于新版本维护，不作为重复初版验收的前置条件。

权限和数据操作在服务端落地，界面禁用按钮只是避免误操作的第二道保护。Electron renderer 不持有 Node 权限或 OSS 长期密钥；preload 只暴露明确的操作接口。云盘文件、服务端控制状态、本地系统加密凭据分别存储。

涉及数据的默认行为：拒绝静默覆盖，失败明确报错，下载完成前不显示最终文件，云盘删除可恢复，OSS 批量修改先验证目标与完整复制，再删除源对象。发生外部服务部分成功时，不伪装成整体成功。

## 存储与迁移

生产升级前先停服务，完整备份 `DATA_ROOT`、`STATE_ROOT` 和权限为 0600 的环境配置。升级时使用独立 `STATE_ROOT`；自动迁移旧控制文件后，检查状态目录、设备列表、个人资料和 OSS 账号是否正确，再开放流量。

先升级并验收后端，再更新桌面客户端；新客户端依赖预览票据等新接口。后端暂时兼容旧客户端的文件 token URL，便于逐台更新设备。

旧版本允许设备令牌读取内部凭据，修复不能证明历史上没有发生过读取。部署修复后，应轮换服务器主令牌、后台密码和 OSS AccessKey，并撤销不再需要的设备。主令牌或后台密码变更会使管理会话和预览票据失效；设备授权应按升级需要明确撤销。

备份必须包含云盘文件、控制状态和回收站。服务器本机回收站仍与服务器共享故障域，不能替代异机备份。OSS 使用独立的版本控制或备份策略。不要在源码、构建日志或备份文件名中写入凭据。

优先使用桌面 Trash 页面恢复文件，在线恢复与文件变更共用锁，目标存在时拒绝覆盖；特殊故障才按服务端说明停服手工恢复。恢复后检查内容，确认成功再处理备份。不要手工把控制 JSON 放回云盘文件目录。

Backups 页面使用 restic 专用加密仓库，分别记录备份成功、完整性检查和恢复验证，三个状态不能互相替代。恢复验证只生成隔离副本，校验后清理数据并保留小型报告；生产恢复依照 [备份说明](../packages/server/BACKUPS.md) 离线执行。备份历史或工作区损坏不得拖垮云盘。

## 并发与失败边界

- JSON 写入和本进程中的破坏性操作串行执行，只有持久化成功后才更新内存状态。此模型按一个服务端进程设计，不应让多个进程同时写同一状态目录。
- 文件浏览请求有版本保护，旧目录、搜索或账号请求不会覆盖新状态。切换范围立即清空旧选择。
- OSS 文件夹是对象前缀，没有跨对象原子事务。复制部分失败时源数据保留，可能留下部分目标副本；删除部分失败会报错，需检查后重试。不要与其他客户端同时修改操作中的前缀。
- 已签发的短期预览/OSS URL 在有效期内可用，设备撤销不会立即收回这些链接。不要分享它们。
- 预览加载失败会限频尝试更新链接，并提供手动刷新。刷新音视频时保留播放位置与暂停状态；具体编码支持仍由系统播放器能力决定。
- 传输状态保存在桌面主进程的有界内存中，跨路由可恢复，但应用退出后不会继续任务。当前没有断点续传或后台持久任务队列，失败后重新发起传输。
- 系统凭据加密依赖登录用户的系统密钥。迁移桌面配置到另一台电脑或重置钥匙串后，可能需要重新授权。

## 验证与发布

`bun run check` 执行安全、文件操作、授权、分页、传输状态和 UI 状态逻辑回归，随后检查四个包、测试与工具脚本的类型，再构建后台、renderer 和 Electron main/preload。

在有图形桌面的 macOS 上，构建后运行：

```sh
bun run --filter @halloween/desktop test:smoke
bun run test:ui
bun run test:media
```

第一项验证真实 Electron 的 preload、进程隔离、IPC、关窗重开和传输快照；第二项使用临时服务端、随机隔离目录和假凭据，验证真实后台页面显示授权码/设备名、等待明确批准、支持拒绝，并防止旧批准响应覆盖新设备页面。第三项用真实 renderer、fixture IPC、本地 WAV/Range 服务和测试时钟验证暂停/播放中刷新、链接失效后拖动恢复，以及损坏媒体的重试限频；响应包含与服务端一致的 sandbox CSP。都不会连接真实 OSS。

发布前还需在目标环境完成：

1. 对部署配置执行 `nginx -t`，确认 TLS、上游端口、数据和状态目录权限；服务仅监听回环地址。
2. 用一个测试设备完成浏览器批准、云盘小文件上传下载与内容校验、预览拖动、撤销设备后拒绝访问。
3. 在专用 OSS 测试前缀验证分页、目录改名、删除、同名冲突。不要拿唯一副本做验收。
4. 在目标 macOS/Windows 上安装产物，检查启动、下载、授权和退出；对需要分发的 macOS 包完成开发者签名和公证。
5. 做一次备份恢复演练，确认控制配置和文件都能恢复。

代码与本地检查通过不等于线上配置、真实 OSS、Windows 安装或 Apple 公证已经验证。CI 配置需推送后才能产生远程运行结果。
